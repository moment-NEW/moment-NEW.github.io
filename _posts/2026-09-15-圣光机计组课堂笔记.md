### 右边 Memory：
主存，按字（word）编址，每个字 32 位 = 4 字节。字地址 0、1、2…… 每 8 个字（8 × 4B = 32 字节）划成一个块（block）：字 0–7 是 block 0，字 8–15 是 block 1，字 16–23 是 block 2。彩色格子表示正在运行的程序访问到的那些字。
### 左边 Cache：
直接映射缓存，共 8 行（line 0–7）。每行有三个字段：Valid Flag（有效位，标记这一行是否有有效数据）、Block Number（标签，记录当前缓存的数据来自哪个内存块，用来区分“同位置但不同块”的情况）、Value（真正缓存的那 4 字节数据）。
红色箭头：展示了映射关系——内存字 3、字 11、字 19 都指向缓存的第 3 行。
核心规则：直接映射

每个内存块只能放进缓存的固定一行，位置由取模决定：

cache line = (block 地址) mod (缓存行数)
缓存有 8 行，所以字 3、11、19 满足 3 mod 8 = 11 mod 8 = 19 mod 8 = 3，全都被映射到第 3 行。这就是图中三支箭头汇聚到同一行的原因。

这个设计的代价

因为多个内存块共享同一缓存行，就必须靠 Block Number（tag） 来区分“现在这行里存的到底是 block 0、block 1 还是 block 2 的字 3”。CPU 访问时把地址拆成三段：低位是行内偏移（4B 一个字 → 2 位），中间是行号（8 行 → 3 位），剩下的高位是 tag，与缓存行里存的 tag 比较；命中且有效位为 1 才能直接用，否则就要把整块数据从内存换进来，把原来占位置的块挤出去——这就是直接映射缓存最容易发生**冲突失效（conflict miss）**的原因：哪怕缓存没满，两个轮流访问的地址只要 mod 8 同余，就会不停地互相顶替。



**简而言之的话**，就是缓存是分行的，每行对应一个固定大小的内存块。CPU为了快速起见每次读取内存都是一块一块取的，这个映射就是为了让你明白CPU索要的内存数据块是否是存在缓存里的那块。为了保证这个是正确的，缓存会以行为单位映射多个块的内存。例如行3对应第三个、第十一个、第十九个块。  
当CPU想访问一个地址的时候，首先会去缓存进行查询。原始的内存地址是连续的一系列数字，缓存会对其做处理，例如缓存字地址19：
tag = 10（block 2）  index = 011（第 3 行）  offset = 11

字 19 在真实内存里占的是字节地址 76–79（19 × 4），它只是个普通的数。  

“块结构”是缓存硬件强加给地址的，不是地址自带的  

缓存设计者先定下两个参数：一行装多大（比如 64 字节）、一共多少行（比如 512 行）。然后才把任何拿来的地址机械地切三段：
```
低 log2(64)=6 位 → 行内偏移
中间 log2(512)=9 位 → 行号
剩下的高位 → tag
```

切法完全由缓存的几何参数决定。同一台机器上，L1 和 L2 的行数、行大小不同，同一份地址会被切成完全不同的三段；如果是全相联缓存（无行号），干脆没有 index 段。所以不是地址“天生”带了块信息，而是缓存拿着尺子去切地址——尺子刻度变了，切出来的块就变了  

现在我们CPU依然要找19这个地址的数据，然后19的地址给到了缓存：  
缓存将其理解为这块内存要到缓存的line3，然后会开始匹配Tag，如果匹配成功，那么就会把这里的valid flag置为1，接着CPU会开始读。  
如果tag不正确，这块内存作废，重新从内存里面读（比如可能这行存的是3或者11的数据块）  
**自始至终，CPU永远使用原始内存地址，只不过缓存巧妙地实现了以块形式的映射和寻址**（当然现代计算机里面多个MMU，会多映射一层，就是前面提到的物理内存变成虚拟内存）

### 缓存命中率
1. 命中率 h（hit ratio）

定义就是一行字：命中的访问次数 ÷ 总访问次数。把程序跑起来统计所有内存访问，命中占的比例就是 h。课件给的典型值是 0.90–0.97，意思是绝大多数访问都被缓存拦下了，根本轮不到内存出场。

2. 缺失率 m = 1 − h

就是命中率的反面，两者互补：命中 95%，缺失就是 5%。有的资料爱用这个口径，本质同一个数。

3. 平均访存时间（核心公式）

T = h × T缓存 + (1−h) × T内存
这里的T是时间，也就是平均访问内存的时间是命中率与内存/缓存读取时间的加权和。
最后，“如果有多级缓存，公式要按显然的方式修改”，指的就是上面那种方式：每一级都有自己的平均访存时间，把他们看成一系列的缓存/内存集合体，我们就可以得到：
```
T = h₁×T₁ + (1−h₁)×h₂×T₂ + (1−h₁)(1−h₂)×h₃×T₃ + …
```

### 汉明码
hamming code就是为了避免电磁辐射导致的位反转产生的（常用于ECC）。它的算法与CRC类似但是排列不同：
数据位和校验位混排，第 1、2、4、8… 位留给校验位，其余位置放数据。以最经典的 Hamming(7,4) 为例——4 个数据位，3 个校验位，共 7 位：

| 位置 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
|---|---|---|---|---|---|---|---|
| 内容 | p1 | p2 | d1 | p4 | d2 | d3 | d4 |

关键规则：**校验位 p_k 负责所有"位置编号的二进制里第 k 位是 1"的位**：

- p1 管位置 1,3,5,7（二进制 xx1）
- p2 管位置 2,3,6,7（二进制 x1x）
- p4 管位置 4,5,6,7（二进制 1xx）

三组覆盖互相重叠，任何一位都恰好被若干组包含。

### 手算一遍（考试大概率考这个）

数据 1011（d1 d2 d3 d4 = 1 0 1 1），偶校验：
注：⊕ 这个符号指的是模加法，就是加起来然后对 2 取模。
```
p1 = d1⊕d2⊕d4 = 1⊕0⊕1 = 0
p2 = d1⊕d3⊕d4 = 1⊕1⊕1 = 1
p4 = d2⊕d3⊕d4 = 0⊕1⊕1 = 0
码字：0 1 1 0 0 1 1
```

假设第 5 位翻转变成了 `0 1 1 0 1 1 1`。接收端把三组校验重新各算一遍，得到 s1=1, s2=0, s4=1，拼成二进制 (s4 s2 s1) = **101 = 5**——出错位置直接被报出来了，翻回去即纠错完成。

这就是汉明码最漂亮的地方：**校验位的位置选取使得"哪组校验失败"恰好构成出错位置的二进制地址**。每组校验本质上是在回答"出错位置编号在这一位上是不是 1"，三组问完，答案自动拼出来。

### 扩展到真实内存（ECC 就是这套东西）

校验位数量 k 要满足 2^k ≥ n + k + 1（n 是数据位数）：

| 数据位 n | 校验位 k | 总位宽 |
|---|---|---|
| 8 | 4 | 12 |
| 16 | 5 | 21 |
| 32 | 6 | 38 |
| **64** | **7** | **71** |

这就是为什么 ECC 内存条是 72 位宽而不是 64 位——64 数据 + 7 校验 + 1 额外整体校验位。多出来的那一位构成扩展汉明码（SEC-DED）：纯汉明码最小距离是 3，能纠 1 位错；若同时错 2 位，syndrome 会指向一个错误的位置，改了反而更错。加上整体奇偶位后最小距离变 4，可以**纠 1 位、同时发现 2 位错**——double error 只报错不乱改，交给上层处理。

补充两点：
- 开销随字长摊薄：8 位数据要 50% 冗余，64 位只要 12.5%，所以 ECC 按整个字（64 位）编码而不是按字节
- 通用规律：最小距离 d 的编码，纠 t 位错需要 d ≥ 2t+1

SDRAM(Synchronous DRAM)

把 DRAM 的所有操作都挂到系统总线时钟上的 DRAM——"Synchronous" 同步的是时钟（tick generator）。
这里elona举了个时间的例子，其实是在说DRAM的问题：
控制器送地址、拉 RAS/CAS,然后只能干等，等够 t_AA 才能取数据。问题在于：芯片什么时候好，控制器不可预测，只能按最坏情况傻等，或者反复询问。总线时钟跑得再快也没用，因为内存这头是“自由散漫”的，两边的节拍对不上。

内存控制器不再“发完命令干等”，而是和芯片约定：“第 3 个时钟沿数据准到”(这个约定就是 CL,Cas Latency 等参数)。因为延迟是以时钟周期数明码标价的，控制器拿到了可预测性——发出读命令后，它精确知道数据哪一拍回来，中间这几拍就可以去干别的：发出下一个命令、访问另一个 bank……流水线就转起来了。这就是为什么 SDRAM 的有效带宽远超异步 DRAM:不是单次变快了，是等待被填满了。  
给一个起始地址后，后续数据每个时钟沿自动吐一个，连发一串(比如一次 8 个字),这个称为burst，和DMA里面那个概念一样，利于Cache。

### external memory
这块通常称之为储存。磁带，磁盘，光盘，SD卡都属于这个范畴。  
这种内存通常可以在离电的情况下长期储存  
RAID:（Redundant Array of Independent Disks，独立磁盘冗余阵列）指用多个物理磁盘组成一个阵列，对操作系统而言呈现为单个逻辑磁盘，数据分布在阵列的各物理盘上，并用部分容量存储冗余校验信息，使得某块盘故障时数据可恢复。通常分为RAID1345这几种：
| 级别 | 名称 | 冗余方式 | 特点 | 最少盘数 |
|------|------|----------|------|----------|
| RAID 0 | 非冗余分条 | 无 | 不是"真"RAID，只为提速；坏一块全丢 | 2 |
| RAID 1 | 镜像 | 每块盘一块副本盘 | 可靠性最高，容量利用率 50% | 2 |
| RAID 2 | 汉明码冗余 | 位级分条 + 一个专门的汉明校验盘（ECC） | 可纠正一位错，现已不用 | 3 |
| RAID 3 | 位交叉奇偶校验 | 位/字节级分条 + 1 块专用校验盘 | 所有盘并行访问，只检错不纠错 | 3 |
| RAID 4 | 块交叉奇偶校验 | 块级分条 + 1 块专用校验盘 | 支持独立读，但校验盘是**写瓶颈** | 3 |
| RAID 5 | 块交叉分布式校验 | 块级分条，校验分散到所有盘 | 消除校验盘瓶颈，**最常用** | 3 |
| RAID 6 | 双重冗余 | P+Q 双校验（Reed-Solomon 码） | 可同时容忍 2 块盘故障 | 4 |
HHD:HDD（Hard Disk Drive，机械硬盘/硬磁盘驱动器）  
机械硬盘由head磁头，track磁道，width宽度，gap和sector扇区组成   
- sector 扇区
    磁道分段，最小读写单元，传统 512 B
- Gap（间隙）
    磁道上不记录数据的空白间隔，起分隔和缓冲作用：

    扇区间隙：分隔相邻扇区  
    扇区内部：扇区结构 = 前导码（同步/地址信息）+ 数据（512 B）+ ECC 校验码，各字段之间也有间隙  

- Width（这里指磁道宽度 Track Width）
    每个同心圆磁道的物理宽度：

    磁道越窄，同样半径内能容纳的磁道越多 → 道密度（TPI，每英寸磁道数）越高 → 容量越大。
    但磁道太窄要求磁头定位更精确，且容易受相邻磁道干扰
（此外还有个platter表示一块磁盘片）


CAV（Constant Angular Velocity，恒定角速度）
指磁盘以固定转速旋转（如 7200 rpm），每个磁道上的扇区数相同。

由此带来的特点：

每个磁道容量一样，但外圈磁道周长更长 → 外圈的位密度更低，外圈空间被浪费了  
换磁道读写时不用调速，控制电路简单 → 机械硬盘普遍采用
对比 CLV（恒定线速度）：CD 光盘用的方案，内外圈线速度一致（位密度处处相同），但转速要随磁头位置变化，适合顺序读整张光盘

- Seek Time
寻道时间  
磁头移动到目标磁道的时间，平均约 5–10 ms
- Rotational Latency
旋转延迟  
目标扇区转到磁头下方，平均为半圈：60/(2×RPM) 秒
- Access Time
存取时间  
寻道时间 + 旋转延迟（定位数据的时间）
- Transfer Time
传输时间  
数据量 ÷（转速 × 每道容量）
- Command Overhead
命令开销  
控制器解析命令的时间，通常忽略不计
- RPM
转速  
每分钟转数，常见 5400 / 7200 / 10000 / 15000

### 磁盘IO时间
CPU进行一次IO需要：
![课件：磁盘 I/O 传输的一般时序（寻道 + 旋转延迟 + 数据传输）](/img/coa-disk-io-timing.png)
1. Wait for Device（等待设备） 磁盘可能正在处理别的请求，你的请求只能在队列里排队。这段时间磁盘没在为你服务。

2. Wait for Channel（等待通道） CPU 到磁盘之间的 I/O 通道/总线被占用，还得等通道空闲才能下达命令。

3. Seek（寻道） 音圈电机驱动磁头臂移动，从当前磁道移到目标磁道。这是机械动作，是最耗时的部分（毫秒级）。

4. Rotational Delay（旋转延迟） 磁头到位后，还要等目标扇区转到磁头正下方。平均等半圈：60/(2×RPM)。如 7200 rpm 的盘 ≈ 4.17 ms。

5. Data Transfer（数据传输） 盘片继续旋转，磁头把扇区数据读出（或写入），耗时 = 数据量 ÷ 磁盘传输速率。
设备忙的时间就是除了1之外的时间。
