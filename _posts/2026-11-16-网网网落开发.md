# 分层与封装（Encapsulation）
TCP/IP 模型从上到下：

- 应用层：HTTP、DNS、SMTP、SSH
- 表示层 / 会话层
- 传输层：TCP、UDP、QUIC
- 网络层：IPv4、IPv6
- 数据链路层：Ethernet
- 物理层

**封装**：HTTP 报文往下走，每过一层套一层壳；接收时每层拆掉自己的头往上交。

| 层 | 加上的东西 | 这时候叫 |
| --- | --- | --- |
| 应用层 | — | HTTP message |
| 传输层 | + TCP 头 | TCP segment |
| 网络层 | + IP 头 | IP packet |
| 链路层 | + 以太网帧头 + FCS | Ethernet frame |

头里装的是地址、端口号、序号、校验和。

# IP 地址与端口
- IPv4：32 位，`192.0.2.10`；IPv6：128 位，`2001:db8::10`
- 本机 localhost：`127.0.0.1` / `::1`
- 连接的一个端点 = 地址 + 端口，如 `192.0.2.10:443`

| 端口 | 服务 |
| --- | --- |
| 80 | HTTP |
| 443 | HTTPS |
| 22 | SSH |
| 53 | DNS |
| 3306 | MySQL / MariaDB |
| 8080 | 开发服务器常用 |

课件里的地址都是文档保留段，抄示例时别当真实 IP。

# HTTP 状态码（Status codes）

| 分类 | 含义 | 常见代码 |
| --- | --- | --- |
| 1xx | Information | 101 Switching Protocols |
| 2xx | Success | 200 OK · 201 Created · 204 No Content |
| 3xx | Redirection | 301 Moved Permanently · 302 Found · 304 Not Modified |
| 4xx | Client error | 400 Bad Request · 401 Unauthorized · 403 Forbidden · 404 Not Found |
| 5xx | Server error | 500 Internal Server Error · 502 Bad Gateway · 503 Service Unavailable |

- **4xx**：请求的问题 → 查 URL、参数、权限。
- **5xx**：服务器的问题 → 查日志和代码。

# HTTP 的版本演进

| 版本 | 年份 | 传输层 | 主要变化 |
| --- | --- | --- | --- |
| HTTP/1.0 | 1996 | TCP | 一条连接一个请求 |
| HTTP/1.1 | 1997 | TCP | 文本报文、持久连接、Host 头 |
| HTTP/2 | 2015 | TCP（实际配 TLS） | 二进制分帧，一条连接并行多请求 |
| HTTP/3 | 2022 | QUIC over UDP | 建连更快；丢包只卡它自己那个请求 |

1.1 的请求只能排队，2/3 一条连接多路复用。方法、状态码、头、URL 各版本含义一致，PHP 无感。

# Cookie 与 Session
HTTP 无状态，登录态靠这套流程维持：

```text
Browser                                Server
  │ 1. POST /login.php                   │
  │    username=alice&password=…         │
  │ ───────────────────────────────────► │
  │ 2. 302 Found                         │
  │    Set-Cookie: PHPSESSID=abc123      │
  │ ◄─────────────────────────────────── │
  │ 3. GET /profile.php                  │
  │    Cookie: PHPSESSID=abc123          │
  │ ───────────────────────────────────► │
  │ 4. 200 OK "Hello, alice!"            │
  │ ◄─────────────────────────────────── │
```

- 用户数据存在服务器 session 里，浏览器只拿号码牌（`PHPSESSID`）。
- 之后同站每个请求自动带回这个 cookie。
- PHP session 细节在 Lecture 4 和 Lab 4。

# Lecture3：CSS
这节课主要讲CSS语法。

## 组合器（Combinators）
组合器描述元素之间的关系。以这段结构为例：

```html
<article>
  <h2>标题</h2>
  <p>第一段</p>
  <p>第二段</p>
  <ul><li><a>链接</a></li></ul>
</article>
```

| 写法 | 含义 |
| --- | --- |
| `article p`（空格） | 后代：article 里**任意深度**的 p |
| `article > p` | 直接子元素：只选 article 的儿子 |
| `h2 + p` | 相邻兄弟：紧跟 h2 的那**一个** p |
| `h2 ~ p` | 通用兄弟：h2 之后**所有**同父的 p |
| `h1, h2, h3` | 分组：一条规则喂给多个选择器 |

空格和 `>` 的区别要结构变深才显出来：若 `li` 里还嵌了 `<p>`，`article p` 选得到，`article > p` 选不到。

课件建议：**选择器链保持短**，一个 class + 一层元素通常够了。`article ul li a` 这种长链，HTML 一插层就断，样式静默失效还难查。

## 盒模型（Box Model）
每个元素都是一个矩形盒子，从里到外四层：

```text
margin  — 推开别的盒子，无背景
border  — 边框
padding — 内容与边框间的填充，背景会延伸到这里
content — width × height，内容本体
```

- **padding 有底色、margin 没有**：想扩大点击区域用 padding，想离别人远点用 margin。
- **垂直 margin 会折叠**：上下相邻盒子取较大值而不是相加，左右不折叠。

默认 `content-box` 下 `width` 只算内容，实际占位 = width + padding×2 + border×2，写 `width: 200px` 的盒子经常放不进 200px 的坑。惯例是全局开 `border-box`，让 `width` 从边框外缘算起，padding 往里挤：

```css
*, *::before, *::after { box-sizing: border-box; }
```

DevTools 里选中元素看到的彩色分层图就是盒模型。

## 定位（Normal flow & positioning）
正常流（normal flow）：块级元素从上到下堆，行内元素从左到右排——不写定位时的默认摆法。`position` 负责把元素从流里拽出来：

| position | 还在流里 | 偏移相对谁 |
| --- | --- | --- |
| `static` | 在（默认） | 不能设偏移 |
| `relative` | 在，**原位还占着** | 自己本来该在的位置 |
| `absolute` | 不在，**坑腾出来** | 最近的**有定位**的祖先 |
| `fixed` | 不在 | 视口（viewport），滚动不动 |
| `sticky` | 在，滚到阈值就粘住 | 滚动容器 |

重叠时谁盖谁由 `z-index` 决定（越大越靠上），只对有定位的元素生效。

经典套路"爹 relative + 儿 absolute"——角标、徽章、浮层的标准写法：

```css
.card  { position: relative; }   /* 爹：当坐标原点 */
.badge { position: absolute; top: 8px; right: 8px; }  /* 儿：锚到右上角 */
```

absolute 单独用会飘到页面左上角，先给父元素加 relative 再说。

## Flexbox：一维布局
给父元素 `display: flex`，子元素沿**主轴**排队。一切围绕两根轴：

- `flex-direction` 决定主轴方向（`row` 水平 / `column` 垂直）；
- **`justify-content` 管主轴对齐，`align-items` 管交叉轴对齐**。

| 属性 | 作用 |
| --- | --- |
| `justify-content: space-between` | 两端对齐，导航栏标配 |
| `align-items: center` | 交叉轴居中 |
| `gap` | 项间距 |
| `flex: 1`（子元素） | 按比例分掉剩余空间 |

经典场景：完美居中 = `display: flex` + 两个 center；导航栏 = `space-between`。

## Grid：二维布局
`display: grid` 直接把容器划成**行 × 列棋盘**，子元素往格子里放。页面骨架的标配：

```css
.page {
  display: grid;
  grid-template-columns: 200px 1fr 300px;  /* 固定 / 自适应 / 固定 */
  gap: 16px;
}
```

| 写法 | 意思 |
| --- | --- |
| `fr` | 剩余空间的份数，同 flex 的 `flex: 1` 思想 |
| `repeat(3, 1fr)` | 三等分 |
| `repeat(auto-fill, minmax(200px, 1fr))` | 响应式卡片神句：能塞几列塞几列，自动加减列 |
| `grid-column: 1 / 3` / `grid-row: span 2` | 跨列 / 跨行 |
| `grid-template-areas` | 给格子起名，布局"画"在字符串里 |

选择口径：**小部件用 flex（一行或一列），整页骨架用 grid（同时管行列）**，两者嵌套用，不是二选一。

## Mobile First vs Desktop First
响应式的机制是同一个 media query，区别在**基线给谁、断点往哪个方向加**：

```css
@media (max-width: 768px) { }  /* ≤768px 生效：desktop first 用 */
@media (min-width: 768px) { }  /* ≥768px 生效：mobile first 用 */
```

- **Desktop first**：桌面完整版当基线，`max-width` 向下**删减**。直觉顺序，但覆盖链越拉越长，容易漏。
- **Mobile first**：手机单列简版当基线，`min-width` 向上**增强**，只增不删。业界推荐。

推荐 mobile first 的理由：手机版是布局最简形态，基线干净；强制先做内容取舍；移动流量过半。考试口径：**`min-width` 向上增强 = mobile first = 渐进增强**。

# Lecture4:PHP
终于讲到服务端了。前三节课写的页面是"死"的——所有人看到的都一样；这节课开始页面在服务器上**现做**，每个人的都可以不一样。

## 服务器上发生了什么
浏览器发请求，Apache 在 `htdocs/` 里翻文件，两种命运：

| 文件 | 处理方式 |
| --- | --- |
| `.html` `.css` `.png` | 从磁盘原样读出、原样发回 |
| `.php` | **PHP 执行脚本**，脚本 print 出来的一切才是响应体 |

三条推论：

- **浏览器永远看不到 PHP 源码**，只能看到执行结果（通常是 HTML）。"查看源代码"里那坨纯 HTML 就是 PHP 吐出来的。
- **每次响应可以不同**——取决于输入、时间、文件、数据库。
- **服务器什么都不记**——每个请求从零开始。登录态全靠 session 才维持得住（Lecture 1 埋的坑，这节填上）。

本地跑 PHP 两条路：装 XAMPP（Apache + PHP + MySQL 一键全家桶，课件指定姿势），或者只装 PHP 解释器用自带服务器 `php -S localhost:8000`——我选的后者，因为 XAMPP 要往 C 盘塞几百 MB。**必须走 localhost 访问，直接双击 `.php` 文件走 `file://` 没有服务器执行代码，看到的要么是源码要么白板**。

## PHP 长在 HTML 里
`.php` 文件本质还是 HTML，中间挖洞塞 PHP：

```php
<p>Today: <?= date('d.m.Y') ?></p>
<ul>
<?php foreach ($labs as $lab): ?>
  <li><?= $lab ?></li>
<?php endforeach; ?>
</ul>
```

- `<?php ... ?>` 执行代码；`<?= expr ?>` 打印一个值（`echo` 的简写）。
- 服务器执行完，浏览器收到的就是纯 HTML（日期已填好、`<li>` 已展开），洞消失了。
- `foreach (...): ... endforeach;` 交替语法专为嵌 HTML 设计，大括号版在这种模板里容易看花眼。
- 纯 PHP 文件（没有任何 HTML）结尾**不写 `?>`**，防止文件末尾意外多输出空行，破坏后面要发的 header。

## XSS：别把用户的话当 HTML 念
场景：评论区。用户提交了一条"评论"，内容是 `<script>...</script>`，然后你要把它展示出来。

危险姿势：

```php
echo $comment;   // 原样吐进 HTML
```

浏览器不区分"这是用户说的话"和"这是网页作者写的代码"，只认 HTML——于是这段 `<script>` 成了页面的一部分，**在每个看到这条评论的访客浏览器里执行**。这就是 XSS（Cross-Site Scripting）：攻击者的脚本借你的域名运行，能偷访客 cookie（包括 PHPSESSID 号码牌）、篡改页面、伪造表单。存储型 XSS 一条评论毒全站。

安全姿势，包一层转义函数：

```php
function e(string $s): string {
    return htmlspecialchars($s, ENT_QUOTES, 'UTF-8');
}
<p><?= e($comment) ?></p>
```

`htmlspecialchars` 把 HTML 语法字符转义成实体，浏览器只显示不解析：

| 原字符 | 转义成 |
| --- | --- |
| `<` | `&lt;` |
| `>` | `&gt;` |
| `"` | `&quot;` |
| `'` | `&#039;` |
| `&` | `&amp;` |

访客看到的就是 `<script>...</script>` 这几个字本身。`ENT_QUOTES` 让单引号也转义（默认只转双引号）——单引号不转的话，数据塞进 `value='...'` 这种单引号属性照样能逃逸。

两条纪律，考试口径：

- **输出时转义，每次都转**（Escape at output, every time）——在数据变成 HTML 的那一刻动手。别指望"入库时洗干净"，展示场景不同需要的干净程度也不同。
- **校验和转义是两个步骤**——validation 决定"收不收"，escaping 保证"显示时不炸"，互不替代，都要做。

## 一个 JSON 接口（endpoint）
PHP 除了吐 HTML 还能吐数据。同一个 `.php`，`Content-Type` 换成 JSON，就是给前端 JS `fetch()` 用的 API：

```php
<?php // public/api.php
session_start();
header("Content-Type: application/json; charset=utf-8");

if (!isset($_SESSION['user'])) {          // 没登录
    http_response_code(401);
    echo json_encode(['error' => 'Not logged in']);
    exit;
}
if ($_SERVER['REQUEST_METHOD'] === 'POST') {
    $in   = json_decode(file_get_contents('php://input'), true);
    $text = trim($in['text'] ?? '');
    if ($text === '') {                    // JSON 也是输入，照常校验
        http_response_code(400);
        echo json_encode(['error' => 'Text is required']);
        exit;
    }
    $_SESSION['messages'][] = $text;       // 存进 session，登录态同款机制
}
echo json_encode($_SESSION['messages'] ?? []);   // GET/POST 最后都回整个列表
```

逐条拆：

- `http_response_code(401)` 设状态码，`json_encode` + `exit` 输出错误收工。**错误也要有正确状态码**，不能 200 的 body 里包一句 error 完事。
- **最大的坑：JSON 请求体不在 `$_POST` 里**。`$_POST` 只填表单格式（`application/x-www-form-urlencoded` / multipart）；JSON body 得自己读原始流 `php://input`，再 `json_decode(..., true)`（`true` = 转成数组而不是对象）。课件原话：JSON is input like any other——是输入就照常校验。
- `$in['text'] ?? ''`：键不存在不报警告，直接给默认值。
- 数据存 `$_SESSION`——开头说的"服务器什么都不记"，全靠 session 这张号码牌背后的存储才存得住。

状态码口径：

| Status | Meaning |
| --- | --- |
| 200 | OK，数据在 body 里 |
| 400 | 请求数据非法 |
| 401 | 没登录 |
| 405 | 方法不允许 |

测试用 `curl -i`，状态行、响应头、body 一次看全。没带 cookie 直接访问就是这个接口的真实反应：

```text
> curl -i http://localhost/lecture4/api.php
HTTP/1.1 401 Unauthorized
Content-Type: application/json; charset=utf-8

{"error":"Not logged in"}
```
